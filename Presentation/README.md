## 발표 자료에 넣을 수 있는 안전한 설명

> “개인 에이전트에서는 AI가 거래조건과 계약 초안을 만들고, 사람이 검토·승인해 변경 이력을 저장하도록 구현했습니다. 출처 오류와 품질검사 실패를 사용자가 확인할 수 있게 하는 복구 처리도 추가했습니다. 이 중 필요한 패턴을 팀 Gmail 기반 에이전트에 선택적으로 적용할 수 있습니다.”

**반드시 구분:** 개인 레포에서 **PR #20~#27 적용** / 팀 레포에서는 현재 **검토할 제안** / 실제 서비스와 발표 시연은 **별도 검증 필요**.

### 추천 발표 흐름 (팀 프로젝트 기준)
1. 현재 구현된 Gmail 연결과 거래정보 추출/후보 생성 흐름 소개 (팀 저장소 최신 기능을 당일 재확인).
2. 사용자 승인 전에 발송하지 않는 안전장치 설명.
3. 개선 후보 K01(근거 검증), K02(실패 복구), K04(견적서 본문과 내부 상태 표시 분리)를 제안으로 소개.
4. 실제 도입한 기능만 라이브 시연; 미도입한 기능은 개인 프로젝트 스크린샷이나 참고 흐름도로 구분.
5. 정상/오류 케이스와 검증 결과 제시. API/실사용 데이터·개인정보는 가상 데이터로 대체.

### 예상 질문
- **이미 팀에 구현됐나요?** 이 README의 K01~K08은 재구현 후보입니다. 팀 레포의 PR과 테스트로 별도 확인해야 합니다.
- **Checkpointer가 120초를 단축하나요?** 개인 앱에서 한 번 측정한 전체 시간은 약 120초였으며, 체크포인터만으로 속도 개선은 입증하지 않았습니다.
- **AI가 자동으로 계약·답장을 확정하나요?** 아닙니다. 사용자 승인, 상태 검증, 발송·출력 차단 규칙을 유지합니다.
- **“해줘”로 구현하려면?** [Team README의 후보 ID와 요청문](../Team/README.md#팀원-선택-구현-해줘-프롬프트)을 AI에게 전달하세요. 이미 구현된 기능이면 변경하지 말도록 지시되어 있습니다.
