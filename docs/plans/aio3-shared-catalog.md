# AIO3 공용 상품 카탈로그 연결

요청: KE KOREA Supabase 프로젝트의 별도 AIO3 상품 저장소를 팀과 함께 사용하고, 기존 문서 작성·LangGraph에서 조회한다. R-02·R-03·R-04·R-11에 대응한다.

## 1. 하나의 공용 카탈로그 조회 경계

- DB 원본은 `aio3_catalog_products`·`aio3_catalog_chunks`·`aio3_catalog_sources`·`aio3_catalog_imports`이며 `aio3_catalog_members`로 명시적으로 허용한다. 이 테이블은 지정한 Supabase 프로젝트에서 별도 구성되며 앱 시작 때 다른 DB에 자동 생성하지 않는다.
- 서버가 postgres/service_role로 접속하더라도 앱 사용자 정수 ID와 `users.supabase_uid`를 멤버 UUID에 연결해 검사한다. 문서 접근 권한과 별개다. 이메일/사용자 metadata를 동적 권한 판단에 사용하지 않는다. 원본·본문·벡터는 타 사용자 개인 문서함에 복제하지 않는다.
- 정확한 SKU/모델코드/전체 제품명이 우선이다. 한글·영문 키워드를 지원하며 실제 인덱스가 있을 때만 동일 모델의 쿼리 벡터를 비교한다. 색상·스위치 불명확 후보와 의미 검색 후보는 임의 확정하지 않는다.
- 기존 PI/PO 작성·수정과 LangGraph의 기존 `create_trade_document` 도구 본문에 같은 조회 경계를 연결한다. 새 그래프 상태·엣지·도구 입력을 추가하지 않는다. 조회 근거는 문서의 `catalog_evidence`에 보존한다.
- 전체 제품이 공용 컴퓨터 상품으로 정확히 확인되면 상품군은 `other`다. 재고 초과와 옵션 불명확을 보완 항목으로 남긴다. 수량은 첨부 재고표 기준이며 실시간 출고·예약을 뜻하지 않는다.
- 원본 단가는 매입/판매 구분이 없으므로 누락 단가를 채우더라도 거래 단가 확인을 요구한다. 기존 명시 단가는 덮어쓰지 않고 CI/PL의 승인 PI 가격·선적 근거에는 적용하지 않는다. 계산·검토·발급·메일 발송 승인은 기존 경계를 유지한다.

## 2. API와 임베딩

설정 → **공용 상품**에서 상품 검색·원본 다운로드·AI 검색 자료 준비를 제공한다. 회사 설정 조회 실패와 별개로 열 수 있고, 네트워크 오류·권한 오류·키 누락은 성공으로 표시하지 않는다. 처리 응답이 유실되면 상태를 다시 읽어 실제 벡터 개수를 확인한다.

모든 응답은 인증·공용 카탈로그 멤버십과 `private, no-store`를 적용한다.

| 요청 | 역할 |
|---|---|
| `GET /api/catalog/status` | 상품·검색 본문·실제 벡터·원본 파일 개수 |
| `GET /api/catalog/search?q=...` | 정확한 식별자/키워드 검색 |
| `POST /api/catalog/search` + `{"q":"..."}` | 본인 키로 쿼리를 임베딩해 같은 프로필 검색. 세션 CSRF 필요 |
| `GET /api/catalog/source` | SHA-256을 검증한 최신 원본 엑셀 |
| `POST /api/catalog/index` | 누락 벡터의 명시적 생성. Bearer 또는 기존 세션 CSRF 필요 |

임베딩은 기존 OpenAI `text-embedding-3-small`/1536과 기존 `UserKeyAccess`만 사용한다. 다른 사용자 키나 서버 공용 키로 대체하지 않는다. 최초 인덱스는 본인이 앱 설정에 키를 등록하거나 지원되는 로컬 실행 환경을 준비한 다음, 로그인 세션으로 `POST /api/catalog/index`를 호출한다. 키를 채팅·그래프 상태·문서·로그에 넣지 않는다. `local_worker`에서 서버가 개인 PC 키를 대신 읽지 않는다.

최대 32개씩 생성하고 모든 배치 성공 뒤 한 트랜잭션으로 저장한다. 공급자 실패·차원/프로필 오류·0 벡터·변경된 본문 해시·삭제된 멤버십은 게시를 막는다. 유료 호출 대기 중 DB 잠금을 잡지 않으며 마지막에 SKU별 본문을 잠그고 해시를 확인한다. 기존 성공 벡터는 보존하고 재호출 시 이미 완료된 행에 다시 과금하지 않는다.

## 3. 검증과 운영 경계

- 생산 검색 SQL과 임시 pgvector PostgreSQL, 합성 상품/계정, 가짜 OpenAI로 멤버/비멤버·부분 실패·이전 성공 보존·옵션·재고·문서 연결을 검증한다.
- 실제 Supabase에는 원본 1개·상품 49개·검색 본문 49개가 등록돼 있고, 확인된 기존 팀 계정의 조회 권한만 허용했다. 계정 정보와 실제 재고표 숫자는 공개 코드·테스트에 넣지 않는다.
- 코드 테스트와 운영 반영은 구분한다. 실제 벡터 생성은 사용 가능한 본인 OpenAI 실행 환경이 필요하며, 실제 앱 로그인·Render 배포 성공을 모의 검사 결과로 표시하지 않는다.
- 관련 코드: `app/catalog/`, `app/trade/common/{models,repository,operations}.py`, `app/tools/create_trade_document.py`. 정상/오류 시험: `tests/test_shared_catalog.py`.
